# 检索不是匹配：在语料上执行查询程序

**Retrieval Is Not Matching: Executing Query Programs over a Corpus**

> ACL 主会投稿中文初版　｜　2026-11-05
> 说明：标注「待补」的表格是尚未完成的 G1/G2 实验，其余数字均来自已完成实验。

---

## 摘要

检索增强生成（RAG）把查询当作一段用于相似度匹配的文本。本文提出一个不同的观点：**查询是一个带变量的程序，检索是在语料上执行该程序。**

执行语义包含五步：编译（需求计划）、赋值（绑定前序答案）、类型检查（绑定门控）、异常处理（回滚）、约束满足（覆盖选择）与终止（全部需求 grounded）。

我们首先用受控干预证明，多跳检索的主导失败不是表示失配：在同一语料、同一标签下，仅改变查询是否绑定前序跳的答案，按跳召回从 **0.915 跌至 0.538**，绑定后恢复到 **0.92 以上**；更强编码器（BGE）与 HyDE 都无法改变这一模式，候选召回在 0.76–0.77 饱和。

基于该诊断实现的 RBG-Exec 在 MuSiQue 上比 IRCoT 高 **+9.5 EM**（200 题，CI [+4.5,+15.0]）；扩到 400 题同池后差距扩大到 **+18.0 EM**（CI [+13.5,+22.8]），且 2/3/4 跳子集分别 +15.1 / +23.8 / +17.1 EM，全部显著。在 HotpotQA 上持平。2×2 消融显示**赋值与约束满足近乎可加**，且绑定单独使用只追平 IRCoT，组合才超过。我们还报告了三个无效机制：绑定门控、共识绑定与回滚，它们在本设置下均未带来增益。

我们同时报告两个负结果：查询侧改写只消除 **9.5%** 的 gap case；LLM 的绝对充分性判定**不是上界**（强制二选一仅 71% 准确，低于监督式 cross-encoder 的 0.280，top-3 仅 0.170）。

最后，我们把检索的控制层形式化为类型化决策问题，并讨论用 22M 决策模型替代每步一次 27B LLM 调用的可行性。

## 1 引言

RAG 的检索器被训练与评估为"给查询找相似文档"。这一形式隐含两个假设：

1. **逐点性**：每个文档可以独立判断相关性；
2. **单一性**：整句查询是一个不可分割的检索意图。

两者在单跳、实体中心的问题上成立，但在组合性问题上失效。我们在 MuSiQue 上做一个直接干预：保持语料、标签、检索器不变，只把前序跳的答案填入后续需求（例如把 `#1 >> spouse` 实例化为 `Steve Hillage spouse`）。结果是：

- 未绑定时，按跳召回从 **0.915** 单调跌至 **0.538**；
- 绑定后，每一跳都回到 **0.92–0.97**，且 BM25 即可达到。

这说明后续跳的失败不是"证据与查询语义不相似"，而是**查询里没有证据所谈论的那个实体**。换言之，gap 是**变量未绑定**，不是**表示失配**。

### 1.1 三种可分离的失败

端到端指标把三种失败混在一起：

| 失败 | 定义 | 本文实测 |
|---|---|---|
| ① 不可达 | 需求证据未进候选（查询未绑定） | 后续跳召回 0.54–0.67 |
| ② 未选中 | 进候选，未排进 top-k | 可达 gap case 的 top-3 仅 0.28 |
| ③ 读不出 | 选中但读者抽取失败 | oracle 绑定下跳级 EM 0.39–0.52 |

分开测量后，归因也随之改变：HyDE 相对同编码器 dense 只 +0.01；IRCoT 的收益主要来自隐式绑定；LLM 打标并非上界。

### 1.2 贡献

- **C1 诊断与因果证据**：把 gap 重述为"未绑定 + 选择错位"，给出直接度量（gap 占比、可达性、closure@k），并用绑定干预给出因果证据。
- **C2 方法 RBG-Exec**：把检索实现为查询程序的执行——编译、赋值、类型检查、异常处理、约束满足、终止；其中绑定门控与回滚用于抑制深跳误差传播。
- **C3 负结果**：查询侧改写不是正确杠杆（9.5%）；LLM 绝对判定不是上界（71% 强制准确率）。
- **C4 评测协议**：chunk 级、oracle 绑定的 gap 协议，可复用为诊断基准。

## 2 相关工作

**假设文档与查询改写。** HyDE 与 Query2Doc 把查询投影到文档分布，改善的是"措辞不像文档"。我们在 95 个真实 gap case 上表明，三种查询侧投影只消除 9.5%–31.6%，而语义匹配器消除 35.8%。

**分解与迭代检索。** Self-Ask、Least-to-Most、IRCoT 把复杂问题拆成子问题或 CoT 步骤。它们在效果上部分实现了赋值，但没有把赋值作为显式操作，也没有判断赋值是否安全。本文的消融显示，赋值单独使用与 IRCoT 打平，**赋值 + 逐需求选证**才超过 IRCoT。

**覆盖式选段与证据充分性。** SETR 识别信息需求并在候选集内做集合选择；SURE-RAG 把充分性作为 set-level 性质用于弃答；PureCover 做覆盖式 rerank。它们的共同限制是**只在候选集内工作**：候选里没有的证据无法被选中（我们的天花板上限 0.61–0.77）。本文把覆盖目标前移到第一段，并对"可不可达"负责。

**检索器训练。** ReSCORE 用 LLM 概率训练 dense retriever，但标签仍是逐文档相关性。本文的诊断表明，逐文档标签与"需求是否被 grounding"是两件事。

**结构化检索与语义解析。** KBQA 的查询图、slot filling 与本文的"程序执行"同源；区别在于本文面向无结构证据，不假设知识库，且赋值对象是**检索得到并需要验证的答案**。

**System One 决策模型。** 近期出现以类型化决策替代文本生成的小模型（如 TypeSafe 的 Jev）。本文的控制层天然是类型化决策问题（能否绑定、是否 grounded、下一步动作），因此这类模型可以作为执行引擎的候选实现；本文不依赖任何闭源服务。

## 3 形式化

### 3.1 查询程序

查询编译为程序 $P=(R,E)$：

- $R=\{r_1,\dots,r_m\}$：带类型的原子需求；
- $E$：依赖边；$r_i$ 的输入可以是前序需求的答案（记作 $\#j$）。

### 3.2 赋值与覆盖

赋值 $\beta: R \to \text{value}\cup\{\bot\}$ 把已得到的答案赋给需求。证据集 $S$ 的覆盖：

$$\mathrm{cov}(S\mid\beta)=\frac{1}{m}\sum_{i=1}^{m}\max_{d\in S}\mathrm{ground}(r_i[\beta],d)$$

### 3.3 两因子分解

对任何只在候选集 $C$ 内选择的方法：

$$\mathrm{cov}(S)\le \underbrace{\frac{|\{i:\exists d\in C,\ \mathrm{ground}(r_i[\beta],d)=1\}|}{m}}_{\text{可达性}}\times\underbrace{\text{选择效率}}_{\le 1}$$

实测（MuSiQue，候选 top-50）：BM25 0.610 / MiniLM 0.760 / BGE 0.765 / HyDE 0.770；选择效率逐点 47–56%，覆盖式接近 100%。

**命题 1（逐点排序无覆盖保证）**：对任意逐点打分器，存在合取需求配置使 top-$k$ 覆盖为 0（$k<m$）；因此逐点 top-$k$ 不存在与排序质量无关的覆盖下界。

**命题 2（覆盖的次模性）**：$\mathrm{cov}$ 对 $S$ 单调次模，贪心达到 $1-1/e$。故给定精确 grounding，选择问题已解决，难度在 grounding 估计。

## 4 方法：RBG-Exec

### 4.1 编译（需求计划）

一次 LLM 调用把查询解析为 1–4 条需求。规则：后一跳可用 `#1` 引用前序答案；实体必须逐字出现在原问题中；最后一跳含占位符。自动计划与金标计划等价（EM 差 +0.020，CI [−0.025,+0.065]）。

### 4.2 赋值（绑定）

把已验证的前序答案填入后续需求。赋值是执行的核心：它把"查询文本"变成"已实例化的需求程序"。因果实验见 §6.2。

### 4.3 类型检查（绑定门控）

朴素赋值把每次抽取的答案直接填入下一跳，误差沿链放大：oracle 绑定下第 4 跳召回 0.897，自动绑定只剩 0.359；端到端损失约 65%。

我们引入**绑定门控** $g(r_i)\in\{0,1\}$，由三个可计算信号决定：

1. **逐字可核**：抽取答案的规范化形式必须出现在所选证据中；
2. **grounding 边际**：该需求 top-1 与 top-2 证据的 CE 分数差（经 sigmoid）超过阈值；
3. **类型兼容**：答案粗类型与需求声明的 answer type 一致。

任一不满足则 $g=0$：**不赋值**，改用「需求文本 + 原问题」联合检索，并把该需求标记为未 grounded。

### 4.4 异常处理（回滚）

若某跳门控失败且预算允许，回滚到上一跳，取其次优答案重新赋值，再重试当前跳。回滚把"错误赋值"变成"可恢复的异常"，而不是让后续所有跳在错误实体上白跑。

### 4.5 约束满足（覆盖选择）

- 对每个已赋值需求，用 cross-encoder 给候选段落打分，得到 $\mathrm{ground}(r_i,d)$；
- 以贪心最大化边际覆盖选择证据集，冗余与预算作为正则；
- 阈值 $\tau\in\{0.3,0.5,0.7\}$ 结果稳定。

### 4.6 终止

当所有需求 grounded，或预算耗尽时停止。停止条件不依赖"模型说停"，可审计：未 grounded 的需求集合就是下一步的检索目标。

### 4.7 执行语义与机制对照

| 程序语义 | 机制 | 状态 |
|---|---|---|
| 编译 | 需求计划 | 已实现 |
| 赋值 | 绑定 | 已实现，有因果证据 |
| 类型检查 | 绑定门控 | 已实现，**待补评测** |
| 异常处理 | 回滚 | 已实现，**待补评测** |
| 约束满足 | 覆盖选择 | 已实现 |
| 终止 | grounded 停止 | 已实现 |

## 5 实验设置

**数据。** MuSiQue validation（200 / 400 题，逐跳标签）、2WikiMultihopQA dev（200 题，由 `evidences` 三元组还原逐跳）、MultiHopRAG（新闻域，200 题，10 段池）、HotpotQA distractor（200 题）。chunk 级协议：40-token 滑窗、stride 20。

**基线。** Vanilla RAG、IRCoT、Self-Ask；检索器 BM25 与 MiniLM；读者 qwen3.6-27b（temperature 0）。

**指标。** 端到端 EM/F1；检索层 Recall@50、gap 占比、closure@3/@10；可达性与选择效率。

**统计。** 按题 1000 次 bootstrap；方法对比为配对 bootstrap。

| 不绑定 | 0.185 | 0.265 |
| 绑定 | 0.330 | **0.405** |

赋值 +0.145/+0.140，覆盖选择 +0.080/+0.075，近乎可加。**赋值单独使用只追平 IRCoT**。

### 6.6 执行语义各机制的作用

| 机制 | MuSiQue EM | HotpotQA EM | 4 跳 EM | 结论 |
|---|---|---|---|---|
| 朴素绑定（基线） | 0.400 | 0.675 | 0.216 | — |
| + 绑定门控（失败不绑） | 0.305 | — | 0.081 | **负结果** |
| + 共识绑定（top-3 多数） | 0.395 | — | 0.216 | 无增益 |
| + 回滚（上一跳换答案） | 0.305 | — | — | 无效 |
| + 上下文感知读者 + 末跳终止 | 0.425 | **0.440** | 0.270 | 只在末跳即答案时有效 |
| **+ 决策层（末跳 vs 合成二选一）** | **0.425** | **0.660** | **0.270** | **在两个数据集上都成立** |

**解读**：
1. 门控失败的原因是绑定错误**不可由表面信号检测**（逐字可核与边际都通过了，但语义漂移）。
2. 固定的"末跳终止"在 MuSiQue 有效，但在 HotpotQA 的 comparison 题上崩掉（0.675→0.440），因为答案需要合成。
3. 因此终止策略本身是一个**决策**：比较末跳答案与合成答案，不一致时让模型二选一。该决策层在 MuSiQue 保持 0.425，在 HotpotQA 恢复到 0.660，是唯一在两个数据集上都成立的机制。

## 7 分析

### 7.1 查询侧改写不是正确杠杆

在 95 个 chunk 级 gap case 上：

| 手段 | gap 消除率 |
|---|---|
| 三路改写（max 合并） | 9.5% |
| 投影成陈述句 | 31.6% |
| CE 语义重排 | **35.8%** |
| CE + 父段落上下文 | 35.8% |

改写改变了"怎么说"，没有改变"缺哪个变量"。

### 7.2 LLM 不是充分性的上界

在 582 个真实 gap case 上（top-20 候选、17.5 万 chunk 库）：

| 打分器 | closure@3 | closure@10 |
|---|---|---|
| BM25 | 0.081 | 0.491 |
| base CE | 0.198 | 0.759 |
| LLM 绝对判定 | 0.170 | 0.737 |
| LLM 蒸馏学生 | 0.227 | 0.749 |
| **GT 监督学生** | **0.280** | 0.753 |

LLM 在难例上低于监督式 CE；强制二选一时仅 71% 选对。**用 LLM 打标训练匹配器不如直接用 GT + 难例挖掘。**

### 7.3 小样本的"上界"不可信

同一 LLM 判定在 64 个 case 上给出 73.4%，扩到 582 个后只有 17.0%。我们据此撤回早期"可达部分有 17 点可学"的结论，并把所有小样本结果标注为不可外推。

### 7.4 控制层作为类型化决策（讨论）

执行程序需要三类决策：能否赋值、是否 grounded、下一步动作。它们都是**从预定义集合中选择**，而不是生成文本。我们用 22M cross-encoder 替代每步 27B LLM 调用，延迟从数百毫秒降到毫秒级；近期 System One 类模型（如 Jev）提供了同一抽象的商业实现。本文不依赖闭源服务，但接口与之兼容。

---

## 8 讨论与局限

1. **端到端增益**：MuSiQue 200 题 +9.5 EM，400 题同池 +18.0 EM；HotpotQA 持平。
2. **门控与回滚是负结果**：表面信号无法检测语义漂移；固定终止策略在 comparison 题上失败，需要决策层。
3. **数据**：三个英文 Wikipedia 数据集（MuSiQue / 2Wiki / HotpotQA）；领域与跨语言语料待补。
4. **理论**：命题 1/2 为草图，缺少带参数的界与证明。
5. **标签**：答案字符串匹配与教师判定一致率约 70%。

---

## 9 结论

检索不是匹配。查询是一个带变量的程序，检索是在语料上执行它：编译、赋值、类型检查、异常处理、约束满足、终止。把这句话做实，需要的不是更强的编码器，而是显式的执行语义。本文给出了诊断、部分机制与可复用的评测协议；完整的执行引擎仍是下一步工作。
