## 0. 论文定位（二选一，由 G0 决定）

**路径 A（方法论文）**：Binding + Coverage 作为方法，端到端显著超过 IRCoT。
**路径 B（诊断/基准论文）**：①②③ 三分框架 + gap 协议 + 负结果，方法作为验证载体。

两条路的共同骨架：

- **C1 诊断**：不可达 / 未选中 / 读不出，三种失败可分离、可度量。
- **C3 负结果**：查询改写只消 9.5%；LLM 绝对判定不是上界（71% 强制准确率）。
- **C4 基准**：chunk 级 gap 协议（oracle 绑定、closure@3/@10、可达性 × 匹配能力）。

## 2. 语料备用方案（按顺序尝试）

1. **2WikiMultihopQA**：官方 JSON（GitHub/Drive）或可用镜像；有逐跳 supporting facts 与 question decomposition。
2. **HotpotQA fullwiki**：需要 Wikipedia dump，重；只作为鲁棒性检查。
3. **领域语料**：R2MED（临床推理检索，EMNLP'26）、BioASQ、PubMedQA；用于验证"术语 gap"是否放大绑定效应。
4. **IIRC**：不完整信息问答，可作为"未绑定"的天然压力测试。

## 3. 方法侧还需要补的

- **绑定失败的回退**：低置信时改走重写/扩候选（E3 的简单回退无效，需要按需求粒度的回退）。
- **覆盖选择的真实口径**：在 175k 库、top-20 上验证（已有：GT 逐点 0.280 vs base 0.198）。
- **成对 + 逐点多任务**：GT 成对 top-10 更好（0.784），逐点 top-3 更好（0.280），合并有空间（暂缓，按用户要求）。
