# 检索不是重排：RAG 的查询槽绑定与证据覆盖

围绕 **"RAG 中 query 与检索证据的语义 gap"** 的完整工作：文献调研 → 机制验证 → 规模化实验 → 诊断修正。

## 一句话

语义 gap 主要不是"query 和证据不够像"，而是**打分时的查询槽放错了对象**。把查询槽从"整句问题"换成"绑定前序答案后的需求"，在计划、读者、重排器、证据预算全部固定的条件下，MuSiQue 200/400 题 EM 从 **0.170 → 0.440 / 0.425**；而把重排器专门在需求对上训练只带来 +0.053 覆盖率（干净计划下 EM 不变，真实计划下 +0.065）。剩余损失可分解为：

$$\text{gap 消除率}=\underbrace{\text{候选可达性}}_{\text{绑定/第一段}}\times\underbrace{\text{匹配能力}}_{\text{CE/蒸馏}}$$

## 四个贡献

- **C1 定位（因果）**：单变量干预证明收益来自**查询槽**，不是编码器、不是重排器的训练分布。
- **C2 方法**：CovBind（需求提升 → 绑定解析 → 查询槽替换 → 逐需求覆盖选择 → 可验证停止）。
- **C3 机制**：覆盖是瓶颈——全覆盖时读者 EM 0.62–0.67，部分覆盖 0.16。
- **C4 负结果**：生成式边际效用在第二跳失效；查询改写只消 9.5% 的 gap；LLM 判定不是上界；六种绑定质控机制无效。

## 局限

- 跨数据集不普适：只有 MuSiQue 显著，2Wiki/HotpotQA 持平。
- 依赖计划质量：需求错了绑定就错，本文未解决计划的可验证性。
- 绑定质控未解决：六种机制均无效。
- "可达性 × 选择效率"仍是经验分解，没有带参数的界。
